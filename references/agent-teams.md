# 子代理与智能体团队：分工规范

## 一、机制选型

| | 子代理（`subagent` / `subagent_fork`） | 智能体团队（`spawn_teammate`） |
|---|---|---|
| 出现在 `list_agents` | 否 | 是 |
| 能被 `wait_agent` 等 | 否 | 是 |
| 结果返回方式 | 完成通知带回正文 | `send_message` + 共享任务板 |
| 共享任务/依赖/写范围 | 无 | `team_task_*`（含 `blocked_by`、`write_scopes`） |
| 可中断 | 无 | `interrupt_agent` |
| 可再建下级 | 仅能建子代理（到 `maxDepth` 拒） | 仅 Lead 能建 |

### 选型规则

| 场景 | 选谁 |
|---|---|
| 单讲次讲义写作 | 子代理 |
| 单讲次盲测复现 | 子代理（`subagent`，不用 fork） |
| 单讲次术语复核 | 子代理 |
| 多讲次并行（≥5） | 智能体团队 |
| 跨讲次一致性检查 | 智能体团队 |

两种机制都是完整工具集，无只读白名单——只读靠任务书纪律。
两种机制都必须在任务书里限定读取范围与输出格式。

## 二、分工原则

| 类型 | 谁做 |
|---|---|
| 取字幕、抽帧、OCR、对齐、校验 | 脚本（主代理调用） |
| 六栏讲义写作 | 子代理（每讲次一个） |
| 盲测复现 | 子代理（fresh 上下文） |
| 术语复核 | 子代理 |
| 参数解析、闸门、最终裁决 | Lead |

## 三、各阶段分工

| Stage | 谁做 | 机制 |
|---|---|---|
| 0 参数解析 | Lead | 自己 |
| 1 probe | Lead | 脚本 |
| 2 代价闸门 | Lead | 问用户 |
| 3 取字幕 | Lead | 脚本（yutto） |
| 4 术语纠错 | Lead | 脚本（glossary_fix） |
| 5 抽帧 + OCR | Lead | 脚本 |
| 6 对齐 | Lead | 脚本 |
| 7 六栏写作 | 子代理 | 每讲次一个；≥5 讲次用团队 |
| 8 装配 | Lead | 脚本 |
| 9 确定性校验 | Lead | 脚本 |
| 9' 盲测 | 子代理 | fresh 上下文 |
| 9'' 术语复核 | 子代理 | 批量 |

## 四、子代理任务书模板

### 4.1 六栏讲义写作

```
你是「讲义写作」代理。工作目录 <工作区>。

## 开工前必读
1. <skill根>/references/contracts/chapter_writer.md
2. <工作区>/courses/<course>/dist/_meta/anchors.json

## 任务
只写这一个文件：<工作区>/courses/<course>/dist/lecture-<NN>.md
输入：anchors.json 中 lecture == "<NN>" 的全部 sections

## 输出格式
按 chapter_writer.md 的六栏结构，每条带锚点与来源标记。
总长 ≤ <字数上限> 字。

## 三条禁令
1. 不得执行任何命令
2. 不得写/改指定文件之外的任何文件
3. 只读任务书指定的文件；读不到如实说明，不猜

## 回执格式
见 chapter_writer.md §七，总长 ≤ 800 字符。
```

### 4.2 盲测复现

```
你是「陌生读者」代理。工作目录 <工作区>。
你未看过原视频、字幕、课件。

## 任务
只读 <工作区>/courses/<course>/dist/lecture-<NN>.md
回答 5 个问题，只依据该文档，不使用先验知识。

## 5 个问题
1. <概念题>
2. <公式题：公式与适用条件>
3. <推导题：复现步骤>
4. <例题题：按文档方法解>
5. <陷阱题：文档标注的易混点>

## 每题输出
答案 / 文档依据（引用原文 ≤50 字 + 锚点）/ 文档未覆盖则明确说明

## 禁令
1. 不得执行任何命令
2. 不得写/改任何文件
3. 不得读任务书指定文件之外的任何文件
4. 不得使用先验知识

## 回执格式
## Q1-Q5：答案 / 依据 / 是否覆盖
## 通过判定：答对 <N>/5，锚点准确 <M>/5
## 文档缺陷
总长 ≤ 1000 字符。
```

盲测必须用 `subagent`（fresh），不能用 `subagent_fork`（继承父级历史，测试失效）。

### 4.3 术语复核

```
你是「术语复核」代理。工作目录 <工作区>。

## 任务
只读 <工作区>/courses/<course>/dist/_meta/corrections.json
逐条判断替换正确性，输出保留 / 回退 / 新增建议。

## 判据
1. 替换后的词在学科上是否成立
2. 该句是否因替换改变原意
3. 同讲次是否有同类错字未覆盖

## 回执格式
## 保留 <N> 条
## 回退 <N> 条：逐条列 from→to 与理由
## 漏改建议 <N> 条：{"from":"...","to":"...","context":"..."}
总长 ≤ 900 字符。
```

## 五、团队拓扑与任务依赖

### 5.1 拓扑

```
Lead
  ├─ 任务板：每讲次一个 task，write_scopes 互斥
  ├─ teammate-1（写作组）：lecture-01..05
  ├─ teammate-2（写作组）：lecture-06..10
  └─ teammate-3（校验组）：全部讲次的 validate + 盲测
```

`write_scopes` 示例：
```
task-01 write_scopes: ["courses/<course>/dist/lecture-01.md"]
task-02 write_scopes: ["courses/<course>/dist/lecture-02.md"]
```

写范围重叠必须拆任务或改串行。并发编辑同一文件失败是静默的。

### 5.2 依赖链

```
取字幕 → 纠错 → 抽帧OCR → 对齐
                              ↓
              写作（每讲次，blocked_by 对齐）
                              ↓
              校验（blocked_by 全部写作）
```

### 5.3 依赖判据

| 情形 | 处理 |
|---|---|
| 下一步输入依赖该结果 | 硬阻塞，必须等到 |
| 结果只用于最后汇总 | 软等待，可做不依赖的活，但不得生产依赖该结论的交付物 |
| 写范围重叠 | 必须串行 |

判据：「下一步能不能在不知道这个结果的情况下继续」——能就不阻塞。

## 六、等待纪律

Lead 等队友：

```
loop:
  list_agents → team_task_list → wait_agent
  timedOut → 回第一步重查
  noProgress → 去任务板确认完成还是失败
```

等待期只做三件事：`list_agents`、`team_task_list`、`wait_agent`。
不产交付物、不读文件、不跑自检。

结束回合前必须先对用户说明「已发起 <什么>，现在结束本回合等回执」。

## 七、歧义上报

| 层级 | 做法 |
|---|---|
| 队友 → Lead | `send_message` 说明卡点，停下等回复 |
| 子代理 → 父代理 | 无通讯路径，任务书须写「遇需澄清 → 不猜，回执『需澄清』栏写明，该部分不做」 |
| 父代理收到「需澄清」 | 必须处理：补材料重发 / 自己查 / 问用户 |

## 八、达上限时

```
1. list_agents 查现有成员
   ├─ 有 inactive 且任务可续 → send_message 唤醒
   └─ 没有 → 尝试创建
2. 创建被拒
   ├─ 必须项 → 向上级汇报一次，按兜底继续
   └─ 非必须 → 本层自己干，交付声明降级
```

判断依据是工具返回的错误信息，不写死上限数字。

## 九、降级路径

| 情形 | 退路 |
|---|---|
| 子代理回执为空或自报越界 | 检查任务书输出格式，重发 |
| 团队建不出来 | 退回子代理串行 |
| 成员卡住或反复 timedOut | `interrupt_agent` → 退回子代理 |
| `noProgress` 但任务板未完成 | `send_message` 唤醒该成员 |
| 子代理层到顶 | 本层自己干，交付声明降级 |
